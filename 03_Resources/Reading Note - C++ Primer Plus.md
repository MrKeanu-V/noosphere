简明则是 C++ = C + OOP + Meta Program（范型）。OOP：object-oriented programming
当然，按照BS老爷子原话，C++，实际上表示C语言的++自增运算，表示C++是从C演化而来的本质。如果你问为什么是C，尽管广泛的传言是因为C的前身是B语言，但根据我的考证，C其实就代表组合Combination，而非正式含义是代表Christopher，因为Christopher Strachey是主持CPL（Basic CPL，即B语言的前身）开发的牵头人。

#### 1.1 C++简介
C语言最初就是为了代替汇编（汇编语言不是机器语言，汇编是JUMP、ADD这些原子指令相近的语言）而出现的，C语言源自贝尔实验室。C++也是资源自贝尔实验室。

![[C++ Primer Plus（第6版）_中文版_带书签_超清.pdf#page=22&rect=154,1303,1518,1481|C++ Primer Plus（第6版）_中文版_带书签_超清, p.22]]

程序语言的类型（或者说“理念”更精确🤔）：

- 面向过程
    - 过程式（BASICAL）：几乎纯线性，大代码块作为流程的一部分？
    - 结构化（C）：自顶向下，一个大任务可以拆解成若干小任务，即有函数的概念，更利于复用代码
- 面向对象（C++）
- 面向组合（Rust）
- 范型编程是C++支持的另一种编程模式，和OOP目标相同，为了复用通用代码

C语言等结构化编程（面向过程）语言的尽管比汇编更清晰、可靠、利于维护，但是仍然难以编写/维护大型程序。

#### ** 1.3 可移植性和标准**
C++一直在致力于可移植性，可移植性就是指同样的程序不需要修改可以编译运行在另一个平台。为了实现可移植性，就需要一个统一的标准。早期是美国国家标准局（American National Standards Institute，ANSI）成立一个专门的C++标准委员会。（ANSI是不是很眼熟？因为C标准也是ANSI制定的，比如最基础的ANSIC码）。随后国际标准化组织ISO也成立一个C++标准位运回。随后又经过多年的努力，终于在199年通过了一项ANSI和ISO统一的C++标准，也就是大家公认的C++起点C++98。在C++98中，添加了异常、RTTI和STL。C++的标准库就是二者（ANSI/ISO C++标准）统一定义的。

番外：ANSI C标准之前的事实标准是《The C Programming Language》一书，作者是Kernighan和Ritchie。如果你见过一种特殊的函数签名方式，即K&R风格函数签名，那你对这两个名字不会陌生。

#### 1.4 C++程序创建过程
![[Pasted image 20260826234215.png|276]]
C++程序的完整创建过程我自己也梳理一下：
1. 文本编辑器 编写 源代码
2. 编译器 编译（也称翻译）源代码 -> 目标代码（Object Code）
3. 链接器 链接 目标代码 -> 可执行程序
4. 用户 运行 可执行程序

**IDE**
这里提到了一个开发者常说常用，却不知定义的概念——IDE。IDE全称为Integrated Development Environments，即集成开发环境。之所以称为集成开发环境，就是因为这些工具软件使得开发者能够在一个主程序里面完成所有的程序开发步骤，即包含上述的：编写、编译、链接和运行。这就是IDE的意义。
![[C++ Primer Plus（第6版）_中文版_带书签_超清.pdf#page=27&rect=127,248,1481,375|C++ Primer Plus（第6版）_中文版_带书签_超清, p.27]]
IDE包含了这些集成化的选项。
    - **Compile** 通常意思是对当前打开的源代码文件进行编译
    - **Build** 和 **Make** 指编译项目中所有源代码文件，**增量编译**
    - **Build All** 指重新编译所有源代码
    - **Link** 指链接源代码编译后的目标代码和库代码
    - **Run** 和 **Execute** 指运行链接后的可执行程序
    - **Debug** 指步进等调试模式运行程序
    - 编译器选择编译模式（**Release** 和 **Debug**）会编译不同的文件，调试模式下编译会插入额外的调试代码

**C++扩展名**
总是看到很多C++程序的扩展，似乎显得自己少见多怪。这里终于看到完整的梳理了，很好。简言之，C++支持的文件后缀，取决于具体的C++实现。
![[C++ Primer Plus（第6版）_中文版_带书签_超清.pdf#page=26&rect=123,1539,1474,1965&color=yellow|C++ Primer Plus（第6版）_中文版_带书签_超清, p.26]]
看下来，比我预期的少，就几类：`.C`、`.cp`、`.cpp`、`.c++`、`.cxx`。我咋印象里还有`.x`之类的呢。
番外：UNIX这类大小写敏感的系统，用小写c表明是C语言文件，而大写C是C++语言文件。

**编译链接**
UNIX下常用编译器是cfront（已经被淘汰）或GNU，大致流程是：`.cc`源码 -> `.o`目标代码 -> `.out`可执行文件
LINUX下常用编译器是g++（来自GNU C++）：
    1. 编译源码 `g++ foo.cxx` -> `.o`
    2. 链接源码 `g++ foo.cxx -lg++` -> `.out`可执行文件
    g++似乎比较统一，一个指令会通用在编译和链接中
WINIDOWS下常用编译器是Cygwin（似乎已被淘汰）和MinGW，命令和LINUX的g++类似，不过最终生成的可执行文件后缀为`.exe`。
#### 有趣的观点
1. **面向过程强调算法，面向对象强调数据**！
2. GP（Generic Programing，范型编程）也可称为**参数多态**

终于看到一本编程类书籍定义**自底向**上了，向立场的左右一样总是糊涂。
**自底向上**：从低级组织（如类）到高级组织（如程序）的处理过程叫做自底向上编程；
作者认为C++的真正优点是方便复用和修改现有的、久经考验的代码。是的，但不利于扩展，我现在发现。
C++作者原话：
> “请注意，OOP 并非万能药。不要简单地把“OOP”等同于“好”。如果你的问题的基本要素中没有与生俱来的层级关系，那么类层级和虚函数对你的代码不会有任何帮助。OOP 的优势在于类层级可以有效地表达很多问题；OOP 的主要弱点在于太多人设法强行用层级模式解决问题。并非所有问题都应该面向对象。也可以考虑使用[普通类](https://www.stroustrup.com/bsfaqcn.html#class)（plain class）、[泛型编程](https://www.stroustrup.com/bsfaqcn.html#generic)和独立的函数（就像数学、C，以及 Fortran 中那样）作为解决问题的方案。”

#### C++之父的FAQ
C++之父 **[Bjarne Stroustrup](https://www.stroustrup.com/index.html)**（下文简称BS）在个人主页有关C++部分的FAQ栏目竟然回答了，我使用C++以来一直困惑的问题——**为什么C++允许不安全的代码**？
原文链接：[Why CPP alow unsafe code?](https://www.stroustrup.com/bs_faq.html#unsafe)

BS老爷子给了以下几点答案：
>- 为了直接访问硬件（例如，把整数当作指向设备寄存器的指针）
>- 为了获取最佳的运行时效率和空间效率（例如，不检测访问数组元素的操作（是否越界），不检测访问对象的指针（是否有效））
>- 为了和 C 兼容

根本原因上我认为就两个原因，**兼容C**和**极致的效率**，而为此特地在编译期违反**静态类型**的安全机制。这也是为什么好的C++代码效率总是最顶级。但在今天，这一部分理念我看来也成了C++的一大障碍；比如使用容器时，开发者需要重复的添加很多越界之类的安全判断，这已然成了冗余。

对此，BS老爷子的原话是：
>所以，当你并不需要以上三种特性时，最好避免有如瘟疫般的不安全代码：
>    - 不要用转换（cast），
>    - 不要将数组用作接口（如有必要，请将它们隐藏于高效函数和类的内部，而使用合适的 string、vector 等编写其余代码），
>    - 避免 void*（如果你真的需要它们，请将它们限制于低级 (low-level) 函数和数据结构的内部，并且为用户提供类型安全的接口（通常是模版 (template)）），
>    - 避免联合体（union），
>    - 如果你对指针的有效性存有任何怀疑，请用智能指针（smart pointer），
>    - 不要“赤裸裸”地使用 new 和 delete（使用容器，资源句柄等），
>    - 不要使用 ...风格的函数（例如 printf）。
> 
>几乎所有 C++ 代码都能遵循这些简单的规则。**请不要因为你编写 C 代码或者 C 风格的 C++ 代码时不能遵循这些规则而认为 C++ 不安全。**

嗨呀，最后一句嘲讽意味拉满🤣。编写C++就是需要遵循这吧啦吧啦一长串的规则，这么多年大家都是这样过来的。如果你的C++程序不安全，那是你不安全，而非C++不安全😅。P.S. 流汗黄豆是我替BS老爷子添加的。

有趣的发现，FAQ里BS老爷子还提到了为什么C++没有提供官方的GUI库，这确实也是一个容易被人忽略，但很有意义的问题。BS老爷子的解释是提供官方GUI库不是一个技术问题，而是一个可行性问题。因为C++已经有了很多商用的或开源的GUI库了，每个GUI库有自己的用户群，他们不会愿意为别的GUI库声明标准。这就很难形成统一的标准。

最后补充一点BS老爷子有趣的名言：
>  - _"C makes it easy to shoot yourself in the foot; C++ makes it harder, but when you do it blows your whole leg off"_.
> 
>    (_“C容易让你开枪时不小心打到自己的脚，C++虽然不这么容易，但是你如果真这么做了，它会把你整条腿轰掉”_)
>  - _"There are only two kinds of languages: the ones people complain about and the ones nobody uses"_.
>  
>      (_“只有两种语言：一种被人抱怨，而另一种没人使用”_)
>  - _"C++ Is my favorite garbage collected language because it generates so little garbage"_.
>  
>      (_“C++ 是我最钟爱的垃圾回收语言，因为它几乎不产生垃圾”_)

BS老爷子是在C++获得一定程度的成功之后，才添加了模版，并在随后改进了模版形成了范型编程。也是在模板改进后，人们意识到了范型的重要性，因此称C++是OOP+范型。
