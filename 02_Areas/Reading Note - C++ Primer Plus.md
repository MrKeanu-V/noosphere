简明则是 C++ = C + OOP + Meta Program（范型）。OOP：object-oriented programming
当然，按照BS老爷子原话，C++，实际上表示C语言的++自增运算，表示C++是从C演化而来的本质。如果你问为什么是C，尽管广泛的传言是因为C的前身是B语言，但根据我的考证，C其实就代表组合Combination，而非正式含义是代表Christopher，因为Christopher Strachey是主持CPL（Basic CPL，即B语言的前身）开发的牵头人。

#### 1.1 C++简介
C语言最初就是为了代替汇编（汇编语言不是机器语言，汇编是JUMP、ADD这些原子指令相近的语言）而出现的，C语言源自贝尔实验室。C++也是资源自贝尔实验室。

![[C++ Primer Plus（第6版）_中文版_带书签_超清.pdf#page=22&rect=154,1303,1518,1481|C++ Primer Plus（第6版）_中文版_带书签_超清, p.22]]

程序语言的类型（或者说“理念”更精确🤔）：

- 面向过程
    - 过程式（BASICAL）：几乎纯线性，大代码块作为流程的一部分？
    - 结构化（C）：自顶向下，一个大任务可以拆解成若干小任务，即有函数的概念，更利于复用代码
- 面向对象（C++）
- 面向组合（Rust）
- 范型编程是C++支持的另一种编程模式，和OOP目标相同，为了复用通用代码

C语言等结构化编程（面向过程）语言的尽管比汇编更清晰、可靠、利于维护，但是仍然难以编写/维护大型程序。

> “对象是类的特定实例，而类定义了数据的存储和使用方式”

#### 1.3 可移植性和标准
C++一直在致力于可移植性，可移植性就是指同样的程序不需要修改可以编译运行在另一个平台。为了实现可移植性，就需要一个统一的标准。早期是美国国家标准局（American National Standards Institute，ANSI）成立一个专门的C++标准委员会。（ANSI是不是很眼熟？因为C标准也是ANSI制定的，比如最基础的ANSIC码）。随后国际标准化组织ISO也成立一个C++标准位运回。随后又经过多年的努力，终于在199年通过了一项ANSI和ISO统一的C++标准，也就是大家公认的C++起点C++98。在C++98中，添加了异常、RTTI和STL。C++的标准库就是二者（ANSI/ISO C++标准）统一定义的。

番外：ANSI C标准之前的事实标准是《The C Programming Language》一书，作者是Kernighan和Ritchie。如果你见过一种特殊的函数签名方式，即K&R风格函数签名，那你对这两个名字不会陌生。

#### 1.4 C++程序创建过程
![[Pasted image 20260826234215.png|276]]
C++程序的完整创建过程我自己也梳理一下：
1. 文本编辑器 编写 源代码
2. 编译器 编译（也称翻译）源代码 -> 目标代码（Object Code）
3. 链接器 链接 目标代码 -> 可执行程序
4. 用户 运行 可执行程序

**IDE**
这里提到了一个开发者常说常用，却不知定义的概念——IDE。IDE全称为Integrated Development Environments，即集成开发环境。之所以称为集成开发环境，就是因为这些工具软件使得开发者能够在一个主程序里面完成所有的程序开发步骤，即包含上述的：编写、编译、链接和运行。这就是IDE的意义。
![[C++ Primer Plus（第6版）_中文版_带书签_超清.pdf#page=27&rect=127,248,1481,375|C++ Primer Plus（第6版）_中文版_带书签_超清, p.27]]
IDE包含了这些集成化的选项。
    - **Compile** 通常意思是对当前打开的源代码文件进行编译
    - **Build** 和 **Make** 指编译项目中所有源代码文件，**增量编译**
    - **Build All** 指重新编译所有源代码
    - **Link** 指链接源代码编译后的目标代码和库代码
    - **Run** 和 **Execute** 指运行链接后的可执行程序
    - **Debug** 指步进等调试模式运行程序
    - 编译器选择编译模式（**Release** 和 **Debug**）会编译不同的文件，调试模式下编译会插入额外的调试代码

**C++扩展名**
总是看到很多C++程序的扩展，似乎显得自己少见多怪。这里终于看到完整的梳理了，很好。简言之，C++支持的文件后缀，取决于具体的C++实现。

番外：UNIX这类大小写敏感的系统，用小写c表明是C语言文件，而大写C是C++语言文件。

**编译链接**
UNIX下常用编译器是cfront（已经被淘汰）或GNU，大致流程是：`.cc`源码 -> `.o`目标代码 -> `.out`可执行文件
LINUX下常用编译器是g++（来自GNU C++）：
    1. 编译源码 `g++ foo.cxx` -> `.o`
    2. 链接源码 `g++ foo.cxx -lg++` -> `.out`可执行文件
    g++似乎比较统一，一个指令会通用在编译和链接中
WINIDOWS下常用编译器是Cygwin（似乎已被淘汰）和MinGW，命令和LINUX的g++类似，不过最终生成的可执行文件后缀为`.exe`。

#### **C++之父的FAQ**
C++之父 **[Bjarne Stroustrup](https://www.stroustrup.com/index.html)**（下文简称BS）在个人主页有关C++部分的FAQ栏目竟然回答了，我使用C++以来一直困惑的问题——**为什么C++允许不安全的代码**？
原文链接：[Why CPP alow unsafe code?](https://www.stroustrup.com/bs_faq.html#unsafe)

BS老爷子给了以下几点答案：
>- 为了直接访问硬件（例如，把整数当作指向设备寄存器的指针）
>- 为了获取最佳的运行时效率和空间效率（例如，不检测访问数组元素的操作（是否越界），不检测访问对象的指针（是否有效））
>- 为了和 C 兼容

根本原因上我认为就两个原因，**兼容C**和**极致的效率**，而为此特地在编译期违反**静态类型**的安全机制。这也是为什么好的C++代码效率总是最顶级。但在今天，这一部分理念我看来也成了C++的一大障碍；比如使用容器时，开发者需要重复的添加很多越界之类的安全判断，这已然成了冗余。

对此，BS老爷子的原话是：
>所以，当你并不需要以上三种特性时，最好避免有如瘟疫般的不安全代码：
>    - 不要用转换（cast），
>    - 不要将数组用作接口（如有必要，请将它们隐藏于高效函数和类的内部，而使用合适的 string、vector 等编写其余代码），
>    - 避免 void*（如果你真的需要它们，请将它们限制于低级 (low-level) 函数和数据结构的内部，并且为用户提供类型安全的接口（通常是模版 (template)）），
>    - 避免联合体（union），
>    - 如果你对指针的有效性存有任何怀疑，请用智能指针（smart pointer），
>    - 不要“赤裸裸”地使用 new 和 delete（使用容器，资源句柄等），
>    - 不要使用 ...风格的函数（例如 printf）。
> 
>几乎所有 C++ 代码都能遵循这些简单的规则。**请不要因为你编写 C 代码或者 C 风格的 C++ 代码时不能遵循这些规则而认为 C++ 不安全。**

嗨呀，最后一句嘲讽意味拉满🤣。编写C++就是需要遵循这吧啦吧啦一长串的规则，这么多年大家都是这样过来的。如果你的C++程序不安全，那是你不安全，而非C++不安全😅。P.S. 流汗黄豆是我替BS老爷子添加的。

#### 2.1 进入 C++
C++ 源码文件包含一下元素：
    1. 注释
    2. 预处理器编译指令
    3. 函数头

**分割符和终止符**
分割符是分割前后语句，终止符是结束当前语句，二者有所区别。
FORTRAN使用行尾（换行）作为语句分割符，Pascal使用分号作为分割符，C/C++ 使用分毫作为终止符。
**启动代码**
C++源码（除了动态库这种非可执行程序源码）必须编写 `main` 函数并不稀奇，但却没有地方会调用 `main` 函数。这是其实是编译器会在编译中添加一段**启动代码**，启动代码是程序和操作系统的桥梁，负责调用 `main` 函数运行程序。

**变量为什么使用前必须声明？**
这是一个很好的问题，像 BASIC、 Python 都不用提前声明变量。C++ 是为了避免潜在的问题（主要是方便命名错误提前暴露），而主动添加了这个限制。

#### **有趣的发现**
1. 众所周知，`main` 函数必须有返回值，尽管并不知道这个主函数的返回值有何意义。为此ANSI/ISO C+标准做了妥协，即使 `main` 函数不显式添加反回语句，编译器也会默认添加 `return 0`，而且这条规则只适用于 `main` 函数。
    - 嗯哼，原来 `main` 函数的返回值还是有用的，作为**退出值**表示程序运行是否成功，操作系统（更准确讲是 shell 和 bash）可以接收这个值；惯例是0为正常，非零则异常
2. 原来`//` 是 C++ 风格注释，而 `/**/` 是 C 风格注释；而非单行多行这外在区别
3. C 风格头文件名一般是 `iostream.h` 后缀，而C++则考虑到存在特殊后缀的扩展名（ `.hxx`、`.hpp`），因此统一不适用扩展名；
    另外尽管 `#include "iostream.h"` 和 `#include <iostream>` 相近，但不同，后者引入的是C++版本头文件，支持C++语言特性，如命名空间。
4. `using` 是一个编译指令，比起 `using namespace std;` 更推荐的做法其实引入具体的函数，如 `using std::cout;`，这有点类似 Python 的 `import xx from xx`
5. `<<` 也被称为**插入运算符**，尤其是流运算 `cout << string; `
6. `\n` 和 `endl` 都能实现换行，前者是**转义字符**，后者是**控制符**，虽然功能相同但后者会刷新输出
7. 《C++ Primer Plus》推荐的 C++ 源代码风格，很简要
    1. 每条语句占一行
    2. 每个函数必须要包含{}，且花括号各占一行
    3. 函数体相对花括号进行锁进
    4. 函数名后的圆括号不留空，如 `void Foo()`
8. 在 C99 标准之前，C语言的变量声明和 Pascal 一样，必须声明在函数内的开始位置
9. 第一次听说**函数原型**的概念，~~所谓的前置声明准确的术语就是**函数原型**~~。哦不一样，**函数原型**是指头文件中的函数。以前叫函数原型，现在我们都叫做函数声明了。
10. 在有些语言（就我的经验，这里大概率指的是FORTRAN）中，有返回值的函数称为**函数**（**function**）；没返回值的函数称为**过程**（**procedure**）或**子程序**（**subroutine**）

OOP的本质是设计并扩展自己的数据类型，不同数据类型有各自处理数据的方法，这就进一步引出了封装等概念。
数据千千万，文字、数字、图片等等，有数据就有类型，这和C++是不是强类型无关。有数据就是需要有类型。C++提供了基本数据类型和复合数据类型，这是本书的一种定义。
#### 3.1 简单变量（算术类型）
**C++命名规则**
1. 名称只能使用英文字母（`a`-`z`）、下划线（ `_`）和数字（`0`-`9`）组成
2. 命名首位只能是字母或下划线，不能是数字
3. 区分大小写
4. 同作用域内不能重名，无歧义（这也是为什么不能使用关键字作变量名）

##### **底层实现**
鉴于浮点数的特殊，这里补充一下浮点数在现代计算机中的底层实现。目前普遍采用 **IEEE 754 标准**来存储浮点数，该标准将二进制内存划分为3部分来实现**二进制科学计数法**。浮点数在内存中的布局如下：
``` ASCII
| 符号位 S | 指数位 E | 尾数位 M |
```
其中S表示正负符号占1bit；指数位E指科学计数法的指数，其在内存中**使用偏移码**保存，至于为何使用偏移码，则是避免负数比较大小时**补码**需要的额外硬件逻辑（简单讲就是单一逻辑统一处理指数）；尾数M为有效数字部分，更准确讲是小数部分，因为有个隐含**前导1**，float一般为32位，则尾数M占32-1-8=23位。
则浮点数计算公式为：
> **(-1)^S × (1.M) × 2^(E-o)**
> <small>其中o为偏移量，一般为 `2^(bitwidth(E)-1) - 1` </small>
><small> 如`float`类型浮点数E长度为8，则偏移量`o=127`</small>

下表直观列举了`float`类型浮点数各部分的位数和作用：

| 部分    | 位数   | 作用                    |
| ----- | ---- | --------------------- |
| 符号位 S | 1 位  | 0 表示正数，1 表示负数         |
| 指数位 E | 8 位  | 存储指数（采用偏移码，偏移量为 127）  |
| 尾数位 M | 23 位 | 存储小数部分，由于前导1，实际精度为24位 |
如上，尾数即当前`float`类型的有效精度，转化为十进制后即可得到其在十进制下的有效精度为：
> 2²⁴ = 16,777,216
> **log₁₀(2²⁴) ≈ 7.22**

考虑到二进制下无限循环的小数（如0.1、0.3等）会被截断，因此C/C++标准采取保守的原则，即保证`float`类型在十进制、二进制的任意转换时前6位始终一致。其他类型，同理可以推导得到`double`类型有效数字为15位，而`long double`要根据平台给定位宽来计算。
**注意**：由于上述原因，使用浮点数时应直接避免使用`==`来判断数值是否一致，应当通过容差`epsilon`来判断浮点数是否相等。

#### 4.5 共用体
1. **定义**：**共用体（union），也称联合体**。本质上是一种让多个成员共享同一内存，但同一时刻仅有一个成员生效的复合类型，我一般视其为一种特殊的结构体。和位字段类似，也是为极致内存优化而诞生的一种产物。
2. **底层原理**：Union本身继承自C语言，是C/C++中用于**极致内存复用**和**底层数据重解释**的核心机制。底层使用**内存共享**机制，Union大小等于最大的成员`sizeof`。由于同一时刻仅有一个成员有效，读取非有效成员时是**未定义行为UB**。
3. **实践**

    - **类型双关（Type Punning）**：这是一种非常有趣的实践方式，可用一个联合体来显示类型数值和二进制表示；不过C++20推荐使用`std::bit_cast`

2. **原理**：

#### 4.8 指针、数组和指针算术
1. 指针算术指对指针进行算术运算符计算，指针计算实际是根据类型对指针指向地址进行偏移
    比如`int * ptr`类型指针的算术计算`ptr + 1`实际上是进行的`ptr + 1 * sizeof(int)`；
    另外，我已经尝试过了，`void*`类型指针不能算术计算，编译通常会报错**error: arithmetic on a pointer to void**，非严格编译模式下大多数编译器则是移动1字节
2. C/C++中数组名通常其实就是一个指针，数组的索引本质上是一个进行指针算术计算的语法糖
    **更新**：
    - 底层实现上，数组名和指针确实是两种类型，只是大部分表达式里编译器都会将数组名**隐式退化为数组首元素的指针**进行计算。因此`sizeof`数组名，和`sizeof`指针的结果是不同的。因此原文用“**等价于**”而非“等于”进行描述是非常精准的。
    - 而`[]`运算符在C99标准中就明确了其运算就是 “> The definition of the subscript operator `[]` is that `E1[E2]` is identical to `(*((E1)+(E2)))`.”
3. 数组的地址

4. `->`操作符号本质就是对于**struct**和**class**类型进行成员访问，可概括为`if E1 is class or struct; then E1->E2 <=> (*E1).E2`
5. C++提供了3种管理内存数据的方式：自动存储、静态存储和动态存储
    - **自动存储**：自动存储其实就是作用域中的局部变量，其声明和释放都由程序自动完成，比如函数内的局部变量在进入函数时自动声明，结束时自动释放。位于**栈区**
    - **静态存储**：静态存储则指那些使用`static`修饰的编译期确定的变量，一般位于**静态区**
    - **动态存储**：其中动态存储比较显然，即运行期`new`/`delete`，其变量生命周期是超出当前作用域的。一般位于**堆区**
6. 堆、栈和内存泄漏：这一节浅显讲了一下内存泄漏，主旨就是`new`和`delete`这种动态存储变量的声明和销毁应当成对出现，否则就会导致内存泄漏；即使养成了成对使用`new`/`delete`的习惯，仍然难以避免内存泄漏，最好的方式是使用智能指针来管理这些堆上的数据。

#### 4.9 类型组合
1. 数组、结构体和指针可以通过各种方式进行组合，说是组合，其实就是因为数组变量实际可看作是指针，所以对数组元素的访问可以通过指针和间接成员运算符来访问

#### 4.10 数组的替代品
1. `std::vecot`：就像`std::string`代替C风格的`char *`那样，C++使用模板类`vector`代替数组。其优点也类同，`vector`也是可变长度的动态数组
2. `std::array`：`vector`功能尽管比数组强大，但代价是效率相较于数组会有所降低（主要和扩容等操作有关）。C++11中还引入了模板类`array`来更方便且安全地使用固定长度数组，其和原生数组同样位于栈区，所以效率上也是等同的。
    本质上`std::array`就是对原生数组的薄封装，最显著的优点是：
    - 传递数组参数时不会退化为指针，依旧保留数组信息
    - 完整迭代器支持，因此可以直接使用`sort`等`<algorithm>`库的方法
    - 提供数组赋值语义，支持数组级别的赋值操作
    - 支持越界检查，不仅支持`at()`；在高级别的Debug模式编译设置下，即使普通的`[]`索引操作都会进行越界检查

4. 字符串是以空字符`\0`（ASCII码为0）结尾的字符数组，常量字符串隐式包含了一个空字符结尾；一般对字符串计算长度时也会忽略这个空字符，如`strlen()`
5. 指针与数组紧密相关
6. 程序变量可分为自动变量、静态内存变量和动态内存变量，分别对应栈区、静态存储区（一般也在栈区）和堆区
7. C++提供了`std::string`代替字符数组（C风格字符串），`std::vector`和`std::array`代替原生数组，智能指针代替裸指针

5. 结构体是C++面向对象的基石，访问类成员函数以`.`的形式，即源自结构体访问数据的成员运算符
6. **位子字段Bit Field（或称位域）**：<small>使用C++这么久了竟然才知道这个概念，项目中似乎很少见到使用这东西🫪</small>
    **定义**：位字段支持**精确指定**类或结构体中某个成员变量的内存位宽
    **背景**：位字段的设计可以追溯到C语言诞生之初，核心就两件事：1. 极致节省内存；2. 内存对齐。`Bit Field`这个概念在C语言以及嵌入式等领域通常译为**位域**，在C++领域则译为**位字段**用于强调其为结构体中的特殊字段属性。
    **原理**：本质上位字段是**编译器提供的一种语法糖和内存布局优化机制**，实际上编译器在底层会将位字段变量按照bit位进行打包，在读写位变量时编译器自动进行了位移运算，拿到了实际的位地址。其底层设计和内存布局优化会留在后续再细究。
    **实践**：
    - 位字段的底层实现和编译器和平台强相关，因此可移植性差（位序不确定）；
    - 不能取地址；
    - 存在位移运算，因此读写效率低于正常成员变量；
    - 必须是整型
    - 超出位字段范围的数值会进行取余运算
    **发展**：由于`BitField`的不可移植性，实践中并不建议使用；`std::bitset`等方案是更好的选择，内存优化则直接使用整型对齐。
7. 结构体Struct和联合体Union可视为一体两面的复合类型，Struct的成员是与关系，所有成员同时存在；而Union是或关系，同一时刻仅一个成员存在且有效。
8. 可以使用Union来实现**类型双关**，如
    ``` C++
    /* Type Punning */

    {
        float value;
        uint8_t bytes[4];
    };
    
    union UIntConverter
    {
        unsigned int value;
        uint8_t bytes[4];
    };
    ```
9. 经常可以见到指针声明时的两种写法：`*`跟随变量类型；`*`紧跟变量名。
    C风格使用`int *ptr`，强调`*ptr`为`int`类型，而C++风格使用`int* ptr`，强调`int*`是一种类型。
    我认为C风格是更尊从本意的写法，因为指针变量声明时的`*`表示作用于变量名，即`*ptrname`解引用后的变量时某某类型。而且`int* p1, p2`实际是声明了一个指针，一个整型，这也说明前缀变量名才是忠于设计初衷的指针声明方式。
10. 我过往认为数组索引是语法糖其实是错误的认识，实际`[]`运算符早在C99标准中就明确其运算过程为`(*((E1)+(E2)))`
    C99标准原文：<small>“The definition of the subscript operator `[]` is that `E1[E2]` is identical to `(*((E1)+(E2)))`.”</small>
    正是因为`[]`运算符是这么定义的，而指针计算正好满足交换律，因此`arr[5]`和`5[arr]`是相同的
11. 数组名等价于指针，而非等于指针，两者是有区别的，只是大部分情况编译器将数组名**隐式退化为数组首元素的指针**
12. `.`为**成员运算符**，`->`为**间接成员运算符**；后者在ANSC C的标准中定义就是`E1->E2 <=> (*E1).E2`，底层仍然使用成员运算符

#### 5.2 while 循环
1. `while`循环是没有初始化和更新部分的`for`循环，只有`test-expression`和`Loop body`
2. ANSI C和C++提供了`ctime`/`time.h`库，用来封装底层系统时钟，使用类型`CLOCKS_PER_SEC`来统一单位
    按照C/C++标准，`clock()`函数返回的是CPU时间，且是程序真正占用CPU执行的时间，不是墙上时间。CPU时间具有如下特性：
    - **不包括程序等待 I/O、sleep、被调度挂起的时间**；
    - **多线程时可能比墙上时间走得更快**，因为多个线程的 CPU 时间会累加；
    - **只适合用差值**，即 `end - start`；绝对起点是实现定义的，不必等于程序启动时刻；
    - 如果无法获取或溢出，可能返回 `(clock_t)(-1)`。
    由于不同平台`clock()`返回的数值和类型不同，不等同时钟时间秒，因此使用`CLOCKS_PER_SEC`来转换到时钟时间单位秒。在**POSIX**平台（如macOS、Linux）其值一般是`10^7`；但在**Windows**，其更接近时钟时间，值是`10^3`，不符合ISO C的CPU时间语义。
    P.S. 现代C++使用`<chrono>`来获取真实时间
3. C/C++建立类型别名的方式：`#define`预处理宏、`typedef`关键字
    优先使用`typedef`，因为预处理宏`define`直接在编译期间硬性文字替换，会导致潜在的问题，如`define INTPTR int *`定义别名后，使用`INTPTR pa, pb;`就存在语义不清晰的问题（`int * pa, pb;`，前者是指针类型，后者是整型）

#### **有趣的发现**
1. C++中控制语句和括号间通常的规范是需要添加一个空格用于强化视觉效果。根本上，这是为了区分函数和控制语句，控制语句（如`if`、`for`尽管后接`()`，但其不是函数，而是编译器符号。
2. C++中**任何由值或任何有效的值和运算符的组合都是表达式**，而C++定义**任何表达式都有值**
    常见的连续赋值`x = y = z = 0;`，底层原理其实是因为`=`赋值运算符优先级从右至左，而赋值语句本身是表达式（C++将赋值表达式的值定义为左侧被赋值成员的值），就又构成了新的赋值表达式。
    类似的，还有条件表达式的值被判定为`bool`、
3. 上述第2点强调C++定义**任何表达式都有值**，反过来就是**没有值的就不是表达式**（至少在早期曾是）
    比如关键字、声明语句都不能算作表达式。
    但这就引起了一个问题，`for`的*init*部分只能放表达式，而变量声明语句不能算作表达式，这使得早期的C/C++都必须提前声明变量，而在`for`的*init*中赋值。这样的结果就是存在作用域泄漏命名污染，而且也并不方便。所以后来C++标准就为此~~打补丁~~，将**声明语句视作一种特殊的表达式**
    
4. `for`语法更准确的表述其实是`for (for-init-statement condition; expression)`，因为声明语句这种特殊的表达式自带分号
5. **顺序点sequence point**其实是为了划清表达式修改“环境”的边界，避免表达式内同时对同一个值多次修改
    貌似现代C++已经不再使用顺序点这个概念了，改用**sequenced-before / indeterminately sequenced / unsequenced**这种更细致的划分。理解顺序点的本意就好。

6. 仅就**副作用**而言，前缀格式自操作运算符比后缀格式更好，因为后缀会首先复制一个副本再执行`+1`操作
    这个冷知识虽然早就知道了，但确实没把这点扩展到类![[Pasted image 20261009233415.png]]
7. 逗号`,`存在多种语义：
    1. **逗号运算符**（(`a++, b++)`）
    2. **声明分隔符**（`int a = 1, b = 2;`）
    3. **参数分隔符**（`f(a, b)`）
8. Pascal和BASIC使用`=`作为条件运算符，而C++中`=`符号为赋值运算符，`==`才是条件运算符
9. “是我给你自由过了火💃”：C/C++赋予程序员极大的自由，开发者要为这自由付出更大的代价
10. `while`和`do while`是对`for`的语义清晰化，`for`循环能够实现两者但不易读、不通用

#### 我的理解
我逐渐理解了C++，或者说理解了编程语言。编程语言毕竟是语言，就像自然语言一样。编程语言有它自己的主谓宾、主动宾语法，这就像汉语、英语。在大多数编程语言中，**语句**就是一个**完整句子**，而**表达式**就是一个**作用成分**，就像自然语言中的主语、动词、状语那样。比如，C++中的表达式**具有值**，和**副作用**。

##### **语句**
语句是程序执行的具体单元，类似自然语言中的完整句子，其一般包含若干表达式和符号，具有一定作用。
